# Documentation Standards

Last Updated: May 12, 2026

## 1. Overview

### 1.1 Purpose
To ensure that all Lutervyn documentation is accurate, discoverable, and easy to understand.

### 1.2 Our Philosophy
- **Doc as Code**: For technical docs, keep them close to the code (Markdown in Git).
- **Just Enough Documentation**: Don't over-document; focus on high-value, frequently used information.
- **Up-to-Date or Deleted**: Outdated documentation is worse than no documentation.

## 2. Formatting & Style

- **Language**: Standard American English.
- **Format**: Markdown (`.md`) is the preferred format for all internal and technical docs.
- **Structure**:
  - Clear Title (H1).
  - "Last Updated" date.
  - Table of Contents (for docs > 3 sections).
  - Concise paragraphs and bullet points.
- **Tone**: Professional, direct, and gender-neutral.

## 3. Categories of Documentation

### 3.1 Policy & Process
- Stored in the `.github` directory of the `policy-and-readme` repository.
- Requires formal approval for changes.

### 3.2 Technical Documentation
- Stored in the `/docs` folder of each project repository.
- Includes: API specs, architecture diagrams, setup guides.

### 3.3 Knowledge Base (Wiki)
- Stored in the [Internal Wiki](./Internal%20Wiki%20and%20Knowledge%20Base%20Management.md).
- Includes: FAQs, troubleshooting guides, meeting notes.

## 4. Maintenance & Ownership

- **Owner**: Every document must have an owner (person or team).
- **Review Cycle**: All documents must be reviewed at least annually.
- **Stale Content**: Any document not updated in 18 months will be flagged for review or archiving.

## 5. Tools

- **Git/GitHub**: For versioned documentation.
- **Notion/Confluence**: For the internal wiki and collaborative notes.
- **Mermaid.js**: For diagrams and flowcharts within Markdown.
