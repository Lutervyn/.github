# Vendor Risk Assessment Policy

Last Updated: May 12, 2024

## 1. Purpose

Assesses risks from third-party vendors who access systems or data.

## 2. Vendor Categories

### 2.1 Critical
- Cloud infrastructure
- Payment processing
- Data centers
- Security services
- High data access
- High impact if breach

### 2.2 Important
- SaaS applications
- Monitoring services
- Development tools
- Moderate data access
- Medium impact

### 2.3 Standard
- Office supplies
- Consulting
- Limited system access
- Low impact
- No sensitive data

## 3. Assessment Process

### 3.1 Evaluation

1. Vendor profile
2. Business need
3. Data access
4. Risk level determination
5. Assessment depth set
6. Process initiated

### 3.2 Questionnaire

- Security practices
- Certifications
- Compliance
- Data handling
- Incident history
- Insurance
- References

### 3.3 Verification

1. Information reviewed
2. References checked
3. Certifications verified
4. Past incidents researched
5. Financial stability
6. Legal status

## 4. Risk Scoring

### 4.1 Criteria

- Security posture
- Compliance certifications
- Financial stability
- Industry reputation
- Incident history
- Data sensitivity

### 4.2 Levels

- Green (Low): Approved
- Yellow (Medium): Conditional
- Red (High): Escalation

## 5. Contracts

### 5.1 Requirements

- Data processing agreement
- Security requirements
- Incident notification
- Audit rights
- Data protection clauses
- Liability limitations
- Insurance requirements

### 5.2 Standards

- Confidentiality required
- Access controls required
- Encryption required
- Backup required
- Breach notification (24 hours)
- Annual audit required

## 6. Ongoing Monitoring

### 6.1 Activities

- Annual reassessment
- Compliance verification
- Incident tracking
- Performance monitoring
- Security alerts monitoring
- Service level monitoring

### 6.2 Reviews

- Quarterly meeting
- Service review
- Issue discussion
- Risk re-evaluation
- Feedback provided
- Action items tracked

## 7. Vendor Offboarding

### 7.1 Process

1. Termination notice
2. Data transition plan
3. Access removal
4. Systems transition
5. Data deletion
6. Final audit
7. Offboarding complete
